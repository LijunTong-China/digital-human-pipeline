# 发布模块 · 规划文档(唯一设计来源,代码未动工)

> 目标:成片 `studio/output/final/final_video.mp4` 一键发布到 **抖音 + 小红书**,
> **全流程无人**(自动上传、自动填文案、自动点发布、自动验证结果)。
> 文档先行:改需求先改本文档再写代码。先不写代码,只定方案。

## 0. 目标与边界(2026-10-04 用户拍板)

- 平台:抖音、小红书(两平台均无开放的個人投稿 API → **浏览器自动化**,复用 nb_auto.py 的 Playwright+CDP 接管真实浏览器模式)
- 自动化程度:**全流程无人**,包括点"发布"
- 核心风险(必须写进对策,不许回避):全自动点发布会加大风控概率
  → 对策见 §5(分层防风控体系:环境层/行为层/节奏层/内容层/熔断层)
- **防风控总原则(2026-10-07 重设计拍板):让自动化行为在平台侧看起来像"一个真人用自己熟悉的浏览器在发作品"。任何单点措施都不够,靠五层叠加 + 熔断兜底。**

## 1. 总体流程(七步链)

```
①账号体检 → ②素材校验 → ③元信息生成(标题/简介/标签,LLM) → ④封面截取
→ ⑤发布窗口决策 → ⑥平台发布 → ⑦结果验证 → ⑧发布记录落盘
```

- 入口:`python publish/publish.py`(全平台)或 `python publish/publish.py douyin|xhs`(单平台)
- 每个平台独立"子流程",单平台失败**不阻断**另一平台(互为冗余,最后汇总报告)
- 相比旧版新增:①账号体检(发前先确认登录态与账号健康)、⑤发布窗口决策(发布时间拟人化)

## 2. 各步骤设计

### ① 账号体检(发前必做,失败即跳过该平台)
- 打开创作者中心首页,校验:登录态有效(未跳登录页)、无风控提示横幅、无异常通知
- 顺手做 1~2 分钟**暖场行为**:滚动浏览推荐流、随机停留(见 §5.2,发布前账号要有"正常浏览"痕迹)
- 体检不通过(需要重新登录/出现验证码)→ 记日志 + 跳过该平台,**不尝试自动重新登录**

### ② 素材校验(不花 GPU,本地)
- `final_video.mp4` 存在且 >10MB(坏文件/占位文件拒发,沿用 gfp 坏文件教训)
- 读取 `studio/output/work/topic.json`(标题)与 `voices.txt` 首页(内容上下文)
- 视频时长/分辨率用 ffprobe 读取,写入发布记录

### ③ 元信息生成(publish/content.py,LLM)
- **抖音**:标题 ≤55 字(超限截断)+ 简介正文(口语化 2~3 句)+ 3~5 个话题标签(`#xxx`)
- **小红书**:标题 ≤20 字(硬限,超了发布键禁用)+ 正文 ≤1000 字(带 emoji 分段)+ 3~5 个标签
- 都从 `topic.json` 标题 + `voices.txt` 生成;产物存 `publish/out/<date>_meta.json`,带指纹
  (视频 md5 + 文本 → 已发布过的成片不重新生成文案)
- **跨平台文案必须改写**:同一视频在两平台的标题/文案由 LLM 分别生成,**不允许一字不差同文案发两平台**
  (搬运/营销号特征,风控重点扫描项)
- LLM 环境变量复用 `docker/.env`(LLM_API_KEY 等),不新增密钥

### ④ 封面截取(本地 ffmpeg)
- 小红书**必须传封面**:取开场白中段一帧(形象满高,比首帧好看),`fr_opening` 思路:
  `ffmpeg -ss <开场白时长一半> -i final_video.mp4 -frames:v 1 cover.jpg`
- 抖音可选(默认自动取同帧);封面统一存 `publish/out/cover.jpg`

### ⑤ 发布窗口决策(时间拟人化)
- 发布时间从配置的**时间窗**内随机取,不在整点/半点发布(整点是营销号特征)
- 默认时间窗:白天段 `10:30~11:40`、晚间段 `19:10~21:30`,当日已过窗口则顺延次日
- 每次发布时间随机抖动 ±10 分钟;两平台发布间隔 ≥30 分钟(同一时刻双平台齐发是矩阵号特征)

### ⑥⑦ 平台发布(publish/platform_douyin.py / platform_xhs.py)
统一子流程(两平台同构,细节分叉):

| 环节 | 抖音(creator.douyin.com) | 小红书(creator.xiaohongshu.com) |
|---|---|---|
| 登录态 | 专用 Chrome profile 人工登录一次(同 NotebookLM 方案) | 同左,独立 profile |
| 入口 | 创作者中心 → 发布视频 | 创作者中心 → 发布笔记 → 上传视频 |
| 上传 | 文件选择器喂 final_video.mp4,轮询进度条 100% | 同左(有转码等待,轮询"上传成功") |
| 填表 | 标题/简介/标签,原生 value setter+input 事件(nb_auto 踩过的 Angular 坑通用),逐字符拟人输入 | 标题/正文/标签;**封面上传**(④ 的 jpg) |
| 声明 | 自动选"内容为 AI 生成"声明(AI 口播合规要求,两平台都有此勾选) | 同左 |
| 发布 | 点"发布"按钮(**无人,自动点**) | 同左 |
| 验证 | 跳转后的作品链接/成功 toast | 发布成功页 URL(`xiaohongshu.com/explore/...`) |

### ⑧ 结果验证(失败分支的统一入口)
- 验证信号:跳转 URL 匹配平台作品页正则 + 页面出现成功标识
- 验证失败 → 截图(`publish/out/<platform>_fail.png`)+ 记日志 + **终止该平台,不重试**
  (沿用 NotebookLM"不可用即终止"的铁律:风控/验证码一律不自动重试,烧号)

### ⑨ 发布记录
- `publish/out/publish_log.jsonl`:每平台一行(时间/平台/视频md5/标题/结果/作品URL/耗时)
- 幂等依据:**同一视频 md5 + 同平台已发布成功 → 跳过**(防重跑重复发布,这是全自动流程最危险的坑)

## 3. 配置(进 `studio/config.json → publish` 节,代码不写死)

| 键 | 说明 |
|---|---|
| `publish.platforms` | 要发布的平台列表,如 `["douyin","xhs"]` |
| `publish.douyin.profile` / `publish.xhs.profile` | 各平台专用 Chrome profile 目录 |
| `publish.douyin.cdp` / `publish.xhs.cdp` | 各自调试端口(两浏览器实例并行/串行) |
| `publish.upload_timeout_min` | 上传+转码轮询上限(默认 15) |
| `publish.daily_limit` | 每平台每日发布上限(默认 **1**,新号期) |
| `publish.time_windows` | 发布时间窗列表,默认 `[["10:30","11:40"],["19:10","21:30"]]` |
| `publish.platform_gap_min` | 两平台发布最小间隔分钟数(默认 30) |
| `publish.ai_declare` | 是否自动勾选"AI 生成"声明(默认 true) |
| `publish.circuit_breaker` | 熔断配置:连续 N 次异常即停 N 天(见 §5.5) |

## 5. 防风控体系(五层叠加,全流程无人的底线)

### 5.0 分层总览

| 层 | 防什么 | 核心手段 |
|---|---|---|
| L1 环境层 | 设备/浏览器指纹被识别为自动化 | 真实浏览器+反检测启动参数+指纹一致性 |
| L2 行为层 | 操作轨迹被识别为脚本 | 拟人输入/鼠标/滚动(behavior.py) |
| L3 节奏层 | 发布频率/时间暴露机器特征 | 限频+时间窗随机+新号养成曲线 |
| L4 内容层 | 文案/发布物被识别为批量生产 | 跨平台改写+不追热点式标题+AI声明 |
| L5 熔断层 | 出问题后继续操作把号烧死 | 失败即停+熔断器+冷却期 |

### 5.1 L1 环境层
1. **专用 profile + 非 headless**:每平台独立 Chrome profile,人工登录一次,cookie 长期复用(同 NotebookLM 模式)。**禁 headless**(headless 是最强风控信号)
2. **抹掉自动化痕迹**:启动参数 `--disable-blink-features=AutomationControlled`;CDP 接管真实浏览器(非 playwright.launch),`navigator.webdriver` 为 false
3. **指纹一致性铁律**:同一 profile 永远用同一台机器、同一分辨率、同一时区/语言;**网络与登录时一致**(在哪个 IP 登录就一直在哪个 IP 用,禁机房 IP 漂移、禁挂代理换出口)
4. **UA/版本稳定**:不主动改 UA,跟随浏览器自身版本,避免 UA 与 JS 指纹矛盾(矛盾本身就是风控信号)

### 5.2 L2 行为层(publish/behavior.py 统一提供)
1. **逐字符输入**:打字带随机 50~150ms 字间隔,段落间随机停顿 0.5~2s;不用 `fill()` 一次灌入
2. **鼠标拟人**:关键点击前先移动鼠标到元素附近(带贝塞尔小抖动轨迹),hover 短暂停留再点;不用瞬间 `click()`
3. **浏览行为**:进入创作页后先随机滚动 2~4 次、停留 3~10s 再开始操作;上传等待期间随机滚动/切换 tab,不留"上传完成即秒点发布"的机械时序
4. **操作间随机延迟**:每字段间 1~3s 随机;整个填表流程总时长下限随机(如 40~90s),太快即脚本特征
5. **session 时长拟人**:发布完成后在创作者中心停留 1~3 分钟(看看数据页)再关闭,**不做"发完即关"**

### 5.3 L3 节奏层
1. **每日限频**:`daily_limit` 硬限(新号期默认 1/天),超限记日志跳过
2. **发布时间窗随机**(§2⑤):不整点发、不固定时间发、两平台间隔 ≥30 分钟
3. **新号养成曲线**:新 profile 前 2 周只浏览不发布或极低频发布(每周 1~2 条),再逐步升到目标频率;频率爬坡配置化,不写死
4. **周内变化**:周末/工作日频率允许不同(真人行为有周期性,机械的每天准时一条也是特征)

### 5.4 L4 内容层
1. **跨平台文案改写**:同一视频两平台标题/正文分别生成,禁止同文案(§2③)
2. **AI 声明必勾**:两平台均声明"AI 生成",合规优先(被人工审核抓到未声明 = 加重处罚)
3. **不碰敏感词/夸大词**:LLM 生成文案时给负面清单(最/第一/绝对/赚钱类诱导词),降低机审命中
4. **封面/标题不做完全模板化复用**:元信息生成带随机性(温度/seed),避免历史发布标题句式高度雷同

### 5.5 L5 熔断层(出事保号,宁可少发不可烧号)
1. **失败即停**:验证码/异常弹窗/风控横幅/发布键禁用 → 截图+日志+终止该平台,绝不自动重试(NotebookLM"不可用即终止"铁律)
2. **熔断器**:同一平台**连续 2 次**发布失败或出现风控信号 → 该平台熔断 **3 天**不发布,期间只允许人工介入
3. **信号分级**:
   - 软信号(上传慢、非阻断提示)→ 记录,继续
   - 硬信号(验证码、账号异常提示、发布失败)→ 终止当日 + 熔断计时
4. **冷却期降频**:熔断恢复后第一周降回养成频率,不立刻恢复满频
5. **发布日志即体检数据**:每次发布记录耗时/异常类型,熔断决策基于日志统计而非拍脑袋

## 7. 已知坑预案(从 nb_auto 经验迁移)

- textarea 必须原生 value setter + input 事件(Angular 丢值)——但外层再包拟人逐字符输入(behavior.py)
- 按钮点击必须限定容器范围(防误点同名入口)
- 提交后页面不能关,轮询等结果(生成/上传都耗时分钟级)
- 不可用提示出现即终止(平台维护/风控),不空等
- Windows 原生浏览器 profile 与 Playwright 隔离:同 nb,专用 profile 目录,禁 headless(风控)
