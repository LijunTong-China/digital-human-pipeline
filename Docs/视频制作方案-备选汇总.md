## 2. 方案二（修订版）：NotebookLM 画面 + 原内容换声

### 2.1 核心思路（关键修正）

> ❌ 旧理解（已被否决）：随便生成一段配音配到 NotebookLM 视频上 → 文不对题
> ✅ 修正：**换声不换内容**。配音内容 = 原视频旁白内容，只把"声音"换成目标克隆音色。

```
热点内容 → NotebookLM Video Overview 生成解说视频（免费、画面质量高）→ 下载 mp4
  → ASR 原声：逐句文本 + 句级时间戳（原文案 = 画面内容的文字来源，天然文对题）
  → 克隆音色 TTS 逐句合成【同样的文本】
  → 逐句对齐：槽内 atempo≤1.15 加速 / 顺延+尾帧定格
  → 替换音轨 + 按新时间轴烧字幕
  → 成片
```

产出效果：观众看到的画面、听到的**内容**与原视频完全一致，只有音色变成了目标人（如用户自己录音克隆的音色）。

### 2.2 适用场景

- 需要高质量 AI 解说画面（NotebookLM 分镜/插图/转场质量显著高于自研模板）
- 想用**指定人的声音**讲这条内容（老板IP、知识博主人设）
- 零成本、零显卡

### 2.3 关键技术点

1. **原内容即文案**：不另外写稿。ASR 转写原声得到逐句文本，TTS 只做"换声重述"，内容逐句一致
2. **逐句对齐**（已 demo2 验证）：原句槽 `[S_i, E_i]`，新配音短→句尾补静音；略长→atempo≤1.15；显著长→顺延+尾帧定格，其后时间轴整体平移
3. **字幕从新时间轴生成**，不抄 ASR 原时间戳
4. NotebookLM 自动化：专用 Chrome profile 人工登录一次（Google 风控不拦已登录会话），MCP/Playwright 只操作业务页——**该路径已于 2026-09-26 全流程跑通**（建笔记本→投喂→生成→下载，见 memory）

### 2.4 已知限制

1. 画面内容不可指定（由 NotebookLM 按源材料理解生成）；画面有精确要求时改走方案三/数字人路线
2. 无官方 API，网页改版需维护自动化；免费额度每 5 小时刷新
3. Video Overview 时长较短（实测约 1 分钟），长视频需拆多条

## 3. 方案三（保留）：文案 + TTS 全自研链路

### 3.1 GPU 说明（本次修正重点）

> **原则：GPU 不是负担，是效果上限——只要 GPU 能换来更好的效果，就用 GPU。** 用户可提供远程 GPU 机器（SSH 可达）。

| 部署形态 | GPU | 效果 | 定位 |
|---|---|---|---|
| **本地 CosyVoice2（首选）** | **需要，约 4GB 显存** | **克隆音色自然度更好、情感/语速可控、音色资产不出本地、零调用成本** | **正式版首选**；用户远程 GPU 机器上部署〔历史:现行预置音色走 SiliconFlow API,克隆走服务器 CosyVoice,本地部署未采用〕 |
| SiliconFlow CosyVoice2 API（降级/兜底） | 不需要 | 可用但克隆自然度与可控性弱于本地 | demo3 已验证跑通；**GPU 机器不可用时兜底**，接口层换 provider 即可 |

> 部署规划：tts-service 直接按"本地优先、API 兜底"设计双 provider；GPU 机器（SSH）到位后当天可切换。

### 3.2 链路

```
热点监控选题 → LLM 写口播稿（分句结构见详细设计 1.3）
  → 逐句 TTS（克隆音色）→ 天然句级时间轴
  → 画面：图卡模板（首版；观感升级后续评估）
  → ffmpeg 合成 + 烧字幕
```

### 3.3 画面形态升级路径

方案三是"骨架"（文案→TTS→时间轴→合成全链路，已验证）；画面首版用图卡模板，后续可评估升级（AI 生图已被剔除，数字人见方案六）。TTS、分句结构、合成器均复用。

## 4.5 方案七（新增，用户提案 2026-09-26）：NotebookLM 演示文稿 + 卡通讲解人 + 语速匹配翻页

> 用户提案：NotebookLM 生成演示文档，大模型生成演示讲解，克隆音色配音，加入卡通人形象，按语音播放速度匹配演示文档的翻页节奏生成视频。**已评估：可行，且复用全部已验证资产。**

### 4.5.1 核心思路

```
热点内容 → NotebookLM 演示文稿（Slides，免费，同一套浏览器自动化，Studio 面板已实测存在该按钮）
  → 下载 pptx/pdf → 每页转图片（pdftoppm / ffmpeg）
  → LLM 逐页看图写讲解词（讲的就是本页内容，天然文对题）
  → 克隆音色 TTS 逐页配音 → 得每页讲解时长
  → 画面 = 幻灯片页（主画面）+ 卡通人形象（角落立绘，说话时口型开合/轻微起伏，静态帧切换即可）
  → 翻页节奏匹配语速：每页停留时长 = 该页配音时长，页间硬切（无定格违和问题，比对齐更简单）
  → ffmpeg 合成 + 烧字幕 → 成片
```

### 4.5.2 为什么可行

1. **NotebookLM 演示文稿已实证存在**：2026-09-26 自动化时 Studio 面板可见"演示文稿"按钮（与音频/视频概览并列），同一浏览器自动化链路直接复用
2. **文对题天然满足**：讲解词由 LLM 基于当前页内容生成，配音讲的就是画面上的内容
3. **翻页对齐远比方案二简单**：翻页是硬切，每页时长直接取该页配音时长即可，无画面定格/变速违和问题；页内若需微调可 atempo≤1.15
4. **卡通人形象零 GPU**：立绘 PNG 叠加 + 说话帧（张口）/静默帧（闭口）两态切换，随 TTS 音量包络切换即可有"在说话"的效果；真口型已直接采用 EMV3-Flash，方案②③按场景使用〔现行直接用 EMV3-Flash，方案②全图+GFPGAN / ③特写裁剪，≤129帧，seed43/8步蒸馏/TeaCache〕

### 4.5.3 GPU 注明

| 环节 | GPU |
|---|---|
| TTS 配音 | 本地 CosyVoice2 需约 4GB 显存（首选，效果更好）；API 兜底 |
| 卡通人两态口型 | **不需要** |
| 真口型驱动（可选升级 Wav2Lip/SadTalker） | 需 NVIDIA 显卡（远程 GPU 机器可跑） |

### 4.5.4 关键技术点与风险

1. pptx/pdf 每页转图（pdftoppm 一条命令）；若 NotebookLM 只出 pdf，直接按页渲染
2. 翻页点容差：句间停顿归入页尾，跨页字幕时间轴从音频时间轴直接生成（单一数据源）
3. 风险：NotebookLM 演示文稿的中文质量与页数需实测（同方案二的一票否决级 POC 项）；卡通形象版权（用自绘/已授权素材规避）
