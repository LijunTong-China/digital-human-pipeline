
### 详细步骤说明

#### 步骤1：按照实施文档实施编码

**输入**：
- 实施方案文档（`Docs/05-抖音优先实施方案与可行性评估.md`）
- 阶段性技术规范
- API接口定义（`Docs/03-API接口与数据模型推断.md`）

**输出**：
- 功能代码（根据技术栈选择目录）
- 配置文件

**注意事项**：
- 严格按照文档中的技术方案实施
- 对齐原系统的API接口规范
- 遵循项目编码规范（见下方"编码规范"章节）

#### 步骤2：更新实施进度文档

**文档**：`Docs/00-实施进度记录.md`

**更新内容**：
- 标记对应阶段为"开发中"
- 记录已实现的功能点
- 更新时间戳

**更新示例**：
```markdown
### 阶段2：热点监控与选题（开发中）

**开始时间**：2026-09-15
**状态**：⏳ 开发中

**已实现功能**：
- ✅ 第三方API接入模块
- ✅ 创作者同步功能
```

#### 步骤3：编写单元测试

**测试目录**：项目根目录下的 `tests/` 文件夹

**测试文件命名规范**：
- 单个模块测试：`test_<module_name>.py`
- 功能测试：`test_<feature_name>.py`
- 集成测试：`integration_<feature_name>.py`

**测试文件位置示例**：
```
tests/
├── test_login_service.py          # 阶段1 单元测试
├── test_hotspot_monitor.py        # 阶段2 单元测试（待创建）
├── test_video_production.py       # 阶段3 单元测试（待创建）〔未实施〕
├── test_publish_service.py        # 阶段4 单元测试（待创建）〔未实施〕
└── integration/
    ├── test_hotspot_to_publish.py # 集成测试（待创建）〔未实施〕
    └── test_e2e_workflow.py       # 端到端测试（待创建）〔未实施〕
```

**测试编写要求**：
- 每个功能点必须对应一个测试用例
- 测试用例命名清晰，描述测试内容
- 包含正常场景和异常场景测试
- 测试覆盖率要求：单元验证 > 90%

#### 步骤4：运行单元测试

**运行方式**：
```bash
cd tests
python test_<module_name>.py
```

**验证标准**：
- 所有测试用例必须通过
- 性能测试必须符合要求
- 并发测试必须稳定

**测试输出**：
- 控制台实时显示测试状态
- 生成测试结果表格
- 保存 JSON 格式测试报告

#### 步骤5：更新实施进度文档

**文档**：`Docs/00-实施进度记录.md`

**更新内容**：
- 标记对应阶段为"已完成"
- 记录测试结果和通过率
- 记录测试时间

**更新示例**：

### Python 编码规范

#### 1. 文件头规范
每个 Python 文件头部必须包含模块说明：

```python
"""模块功能说明

详细描述模块的职责、接口、使用方法。

Author: Claude Code
Date: 2026-09-XX
"""
```

#### 2. 导入规范
```python
# 标准库导入
import asyncio
import logging
from pathlib import Path

# 第三方库导入
from fastapi import FastAPI
from pydantic import BaseModel

# 本项目导入
import config
from services.douyin import check_login
```

#### 3. 类命名规范
- 类名：大驼峰命名法（PascalCase）
- 函数名：小写+下划线（snake_case）
- 常量：大写+下划线（UPPER_SNAKE_CASE）
- 私有方法：前缀下划线（_private_method）

#### 4. 类型注解规范
所有函数必须包含类型注解：

```python
async def check_login() -> Dict[str, Any]:
    """检测登录态"""
    pass

async def open_login_page(url: str, timeout: int = 30) -> Dict[str, Any]:
    """打开登录页"""
    pass
```

#### 5. 异常处理规范
```python
try:
    result = await some_operation()
except SpecificException as e:
    logger.error("操作失败: %s", str(e))
    raise
except Exception:  # noqa: BLE001
    logger.exception("未知异常")
    return {"error": str(exc)}
```

#### 6. 日志规范
```python
logging.basicConfig(level=logging.INFO, format="%(asctime)s %(name)s %(levelname)s %(message)s")
logger = logging.getLogger("module.name")

# 日志级别使用
logger.debug("调试信息")
logger.info("一般信息")
logger.warning("警告信息")
logger.error("错误信息")
logger.exception("异常信息")
```

#### 7. 异步编程规范
```python
# 正确的异步函数定义
async def async_function() -> None:
    await some_async_operation()

# 使用 asyncio.sleep 而不是 time.sleep
await asyncio.sleep(1)
```

### API 接口规范

#### 1. RESTful 规范
```
GET    /api/resource        # 获取资源列表
GET    /api/resource/{id}   # 获取单个资源
POST   /api/resource        # 创建资源
PUT    /api/resource/{id}   # 更新资源（完整）
PATCH  /api/resource/{id}   # 更新资源（部分）
DELETE /api/resource/{id}   # 删除资源
```

#### 2. 返回值规范
```python
# 成功响应
{
    "success": true,
    "data": {...}
}

# 错误响应
{
    "success": false,
    "error": "错误信息"
}

# 列表响应
{
    "items": [...],
    "total": 100,
    "page": 1,
    "page_size": 20
}
```

#### 3. HTTP 状态码规范
- 200 OK: 请求成功
- 201 Created: 资源创建成功
- 400 Bad Request: 请求参数错误
- 401 Unauthorized: 未授权
- 403 Forbidden: 禁止访问
- 404 Not Found: 资源不存在
- 500 Internal Server Error: 服务器内部错误

### 配置管理规范

#### 1. 配置文件命名
- 全局配置：`config.py`
- 环境配置：`.env.example`（提供模板）
- 本地环境配置：`.env.local`（不提交到 Git）

#### 2. 配置项命名
```python
# 常量配置使用大写
BASE_URL = "https://example.com"
TIMEOUT_SECONDS = 30
MAX_RETRIES = 3

# 配置类使用小驼峰或下划线
class Config:
    api_key: str
    timeout: int = 30
```

#### 1. 测试文件结构
```python
#!/usr/bin/env python3
"""模块单元测试

Author: Claude Code
Date: 2026-09-XX
"""
import json
import time

    print("❌ 缺少依赖")

TEST_RESULTS: List[Dict[str, Any]] = []


class TestResult:
    """测试结果记录器"""

    @staticmethod
    def record(test_name: str, passed: bool, result: str, **kwargs) -> None:
        """记录测试结果"""
        TEST_RESULTS.append({
            "测试项": test_name,
            "状态": "✅ 通过" if passed else "❌ 失败",
            "结果": result,
            **kwargs
        })


class ModuleTester:
    """模块测试器"""

    def __init__(self, base_url: str = BASE_URL):
        self.base_url = base_url

        pass

    def test_feature_2(self) -> None:
        """测试功能2"""
        pass

    def run_all_tests(self) -> None:
        """运行所有测试"""
        pass


def main():
    """主函数"""
    tester = ModuleTester()
    tester.run_all_tests()


if __name__ == "__main__":
    main()
```

### Git 提交规范

#### 1. 提交信息格式
```
<类型>(<范围>): <简短描述>

<详细描述>
```

#### 2. 类型（type）
- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档更新
- `test`: 测试相关
- `refactor`: 重构
- `perf`: 性能优化
- `style`: 代码格式调整
- `chore`: 构建/工具链相关

#### 3. 范围（scope）〔仓库建立后生效〕
- `login-service`: 登录服务
- `hotspot-service`: 热点监控服务
- `video-service`: 视频生产服务〔对应服务未创建〕
- `publish-service`: 发布服务〔对应服务未创建〕
- `docs`: 文档
- `test`: 测试

#### 4. 示例
```
feat(login-service): 添加手动保活接口

- 新增 POST /api/quant/keepalive/douyin 接口
- 集成到 LangGraph 工作流
- 更新文档说明
```

```
test(login-service): 编写单元测试

- 创建 test_login_service.py
- 覆盖10个测试用例
- 添加性能和并发测试
```

## 📌 质量标准〔适用于常驻 FastAPI 服务;studio 脚本集不在此列〕

### 代码质量标准
- 测试覆盖率：> 90%
- 代码复用率：> 80%
- 函数平均长度：< 50 行
- 类平均长度：< 500 行

### 性能标准
- API 响应时间：< 100ms（P50）
- API 响应时间：< 500ms（P95）
- 并发处理能力：> 100 req/s

### 稳定性标准
- 服务可用性：> 99.9%
- 错误率：< 0.1%
- 平均恢复时间（MTTR）：< 5 分钟
